PANDUAN PEMASANGAN — DIGITAL SAFETY PATROL (MICROSERVICES + DOCKER)
===================================================================

KEBUTUHAN
- Docker Desktop (Windows/Mac) atau Docker Engine + Docker Compose v2 (Linux)
  Cek:  docker --version   dan   docker compose version
- RAM kosong sekitar 3 GB (ada 8 container + MySQL). Build pertama butuh internet dan beberapa menit.

LANGKAH
-------
1. Ekstrak zip, buka terminal di folder yang berisi docker-compose.yml.

2. Buat file .env:
     Linux/macOS : cp .env.example .env
     Windows CMD : copy .env.example .env
   Buka .env dan ganti: MYSQL_ROOT_PASSWORD, DB_PASSWORD, JWT_SECRET, INTERNAL_KEY.
   (JWT_SECRET dan INTERNAL_KEY: teks acak panjang. Password cukup huruf/angka.)

3. PENTING bila sebelumnya Anda pernah menjalankan versi monolith di folder ini:
     docker compose down -v      (menghapus container + volume lama)
   Versi ini memakai volume baru, tetapi langkah ini mencegah bentrok.

4. Jalankan:
     docker compose up --build -d
   Build pertama lama (mengunduh image, npm install, prisma generate). Pantau:
     docker compose ps
     docker compose logs -f auth-service
   Tunggu sampai semua service berstatus "healthy" (sekitar 1-3 menit setelah build).

5. Buka  http://localhost:8080   -> login:  superadmin / admin / petugas  (password: lihat SEED_PASSWORD di .env)
   Cek API gateway & semua service:  http://localhost:8000/api/health

6. (Opsional) Tes otomatis alur lengkap (butuh Node.js 20 di komputer Anda):
     node --test tests/
   Atau dengan alamat/password lain:
     BASE_URL=http://localhost:8000 SEED_PASSWORD=Password123! node --test tests/

PERINTAH BERGUNA
----------------
   docker compose ps                           status semua container
   docker compose logs -f report-service       log satu service (format JSON, ada requestId)
   docker compose logs -f                      log semua service
   docker compose restart report-service       restart satu service
   docker compose up -d --build report-service build ulang + jalankan satu service saja
   docker compose down                         hentikan (DATA TETAP ADA di volume)
   docker compose down -v                      hentikan DAN HAPUS semua data (hati-hati)

Latihan: scaling, mematikan service, restart, dll -> lihat  docs/LATIHAN_DOCKER.md

BILA ADA MASALAH
----------------
- "JWT_SECRET ... wajib" / "INTERNAL_KEY ... wajib": isi di file .env (bukan .env.example).
- Service restart terus: docker compose logs <nama-service>  (cari baris error). Penyebab umum: password di .env
  diganti SETELAH volume MySQL dibuat -> jalankan  docker compose down -v  lalu ulangi langkah 4.
- Port 8080 atau 8000 sudah dipakai: ubah FRONTEND_PORT / GATEWAY_PORT di .env.
- Login gagal "tidak dapat terhubung": gateway/auth belum healthy, cek  docker compose ps.
- Setelah mengubah file di _common/ jalankan  sh scripts/sync-common.sh  lalu build ulang service.
